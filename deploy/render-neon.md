# Бесплатное размещение на Render + Neon

Приложение и Telegram webhook работают на Render, PostgreSQL — в Neon.
После настройки домашний компьютер можно выключать. Семья пользуется
Telegram-ботом. HTTPS-панель доступна только главному аккаунту с обязательным MFA;
остальные участники через бота работают только со своими расходами.
Валюта выбирается через `APP_CURRENCY`: TMT (по умолчанию), RUB, USD, EUR или AZN.
Все суммы вводятся и отображаются в одной выбранной валюте, без пересчёта.

## 1. Подготовьте репозиторий

Загрузите эту версию проекта, включая корневой `render.yaml`, в свой GitHub
репозиторий. Render должен получить доступ к нему; приватный репозиторий тоже
подходит. Не загружайте `.env`, токены и резервные копии базы.

## 2. Создайте PostgreSQL в Neon

1. Зарегистрируйтесь на <https://console.neon.tech/> и выберите Free.
2. Создайте проект. Желательно выбрать регион рядом с Render (в Blueprint
   указан Frankfurt). Если доступен выбор версии PostgreSQL, выберите 17.
3. Откройте **Connect**, выберите базу и роль владельца, отключите **Connection
   pooling** и скопируйте прямую строку подключения вида
   `postgresql://USER:PASSWORD@HOST/DATABASE?sslmode=verify-full`.
   Если Neon показал `sslmode=require`, замените только это значение на
   `verify-full`. Сохраните остальные параметры, включая `channel_binding=require`.
   Приложение проверяет сертификат и имя сервера; более слабый режим в облаке
   не принимается.
4. Эта строка станет `DATABASE_URL` на Render. Отдельный `POSTGRES_PASSWORD`
   или `PGPASSWORD` на Render не нужен. Прямое подключение подходит для одного
   экземпляра приложения и его миграций.

Приложение автоматически создаст таблицы при первом запуске.

При первом запуске валюта закрепляется за базой. Если в ней уже есть расходы
или журнал операций от старой рублёвой версии, укажите `APP_CURRENCY=RUB`.
Позже другая валюта потребует отдельной базы: запуск с несовпадающим кодом
останавливается без пересчёта данных. Если Render-сервис уже создан, добавьте
`APP_CURRENCY` вручную в Environment. Blueprint использует `sync: false` и не
перезаписывает это значение при синхронизации.

**Новая база будет пустой.** Расходы из локального Docker автоматически не
переносятся. Если они нужны, сначала сделайте резервную копию и перенесите
данные в Neon до начала использования облачного бота. Не запускайте локальную
и облачную версии бота одновременно с одним токеном.

## 3. Создайте бесплатный сервис Render

1. Зарегистрируйтесь на <https://dashboard.render.com/> и подключите GitHub.
2. Выберите **New → Blueprint**, затем свой репозиторий.
3. Render прочитает `render.yaml`: один Web Service, Docker, план **Free**.
   Отдельную базу Render создавать не нужно.
4. Заполните запрошенные переменные:

   | Переменная                  | Значение                                        |
   |-----------------------------|-------------------------------------------------|
   | `APP_CURRENCY`              | `TMT`, `RUB`, `USD`, `EUR` или `AZN`; для этого проекта выберите `TMT` |
   | `DATABASE_URL`              | Прямая строка подключения из Neon с TLS         |
   | `TELEGRAM_BOT_TOKEN`        | Токен вашего бота от BotFather                  |
   | `TELEGRAM_ALLOWED_USER_IDS` | Числовые Telegram ID семьи через запятую        |
   | `LLM_API_KEY`               | Ключ Groq                                       |
   | `PANEL_AUTH_KEY`            | Отдельный случайный ключ шифрования MFA, 64 hex-символа |
   | `PANEL_MASTER_USER_ID`      | Единственный Telegram ID главного аккаунта; он должен входить в allowlist |
   | `TELEGRAM_WEBHOOK_SECRET`   | Случайный секрет для проверки запросов Telegram |

   Секрет webhook можно создать локально командой:

   ```sh
   openssl rand -hex 32
   ```

   Скопируйте результат в `TELEGRAM_WEBHOOK_SECRET`. Не используйте токен бота
   или пароль панели вместо этого секрета. Допустимы 32–256 символов:
   латинские буквы, цифры, `_` и `-`.

   Отдельно выполните `openssl rand -hex 32` ещё раз и сохраните новый результат
   как `PANEL_AUTH_KEY`. Он должен отличаться от секрета webhook. Ключ шифрует
   TOTP-секреты в БД: сохраните его в менеджере паролей и не меняйте при обычных
   перезапусках. Общие `PANEL_USERNAME` / `PANEL_PASSWORD` больше не используются.

   Остальные параметры уже заданы в Blueprint: часовой пояс `Asia/Ashgabat`,
   режим `webhook`, модель Groq. При необходимости
   измените их в Render → Environment. Выбор модели зависит от её доступности
   вашему аккаунту Groq.
5. Остановите локального бота перед первым облачным запуском. Для стандартного
   локального проекта можно остановить только приложение, сохранив базу:

   ```sh
   docker compose --env-file .env -f deploy/docker-compose.yaml stop app
   ```

6. Запустите Blueprint и дождитесь статуса **Live**. В логах должны появиться
   `panel listening` и `Telegram webhook enabled`.

Render автоматически предоставляет HTTPS-адрес и `PORT` / `RENDER_EXTERNAL_URL`.
Приложение использует их и само регистрирует webhook; вводить токен бота в URL
браузера не требуется. Если адрес задаётся вне Render, укажите
`PUBLIC_BASE_URL=https://ваш-домен` без пути и параметров.

## 4. Проверьте доступ всей семьи

1. Главный пользователь отправляет боту `/panel` из своего личного чата. Его
   ID должен совпадать с `PANEL_MASTER_USER_ID` и входить в
   `TELEGRAM_ALLOWED_USER_IDS`. Бот выдаёт личную одноразовую
   ссылку настройки на 15 минут; не пересылайте её другим.
2. Откройте ссылку, задайте уникальный пароль длиной 15–256 символов, добавьте
   QR-код в приложение-аутентификатор и подтвердите шестизначным кодом.
   Сохраните 10 одноразовых резервных кодов. QR и секрет обрабатываются локально
   приложением, без внешнего сервиса генерации изображений.
3. Войдите в панель с Telegram ID главного аккаунта, личным паролем и новым кодом
   аутентификатора. Каждый код можно использовать только один раз, поэтому
   после настройки дождитесь следующего кода. Резервный код заменяет TOTP,
   но пароль всё равно обязателен.
4. В приватном окне убедитесь, что панель перенаправляет на `/auth`, а
   `/api/users` отвечает 401 без авторизации. Вход только по паролю запрещён.
   В панели есть «Выйти» и страница «Безопасность» для замены пароля или MFA.
   Главный аккаунт может просматривать и редактировать расходы всей семьи.
   Проверьте `/panel` из другого разрешённого Telegram-аккаунта: бот должен
   объяснить, что панель доступна только главному пользователю, без ссылки.
5. Каждый участник открывает `https://t.me/ИМЯ_БОТА`, нажимает Start и пишет
   «кофе 350». Его ID должен присутствовать в allowlist на Render.
6. Проверьте появление записи в панели. В Telegram каждый участник работает
   со своими расходами; панель семьи доступна только главному аккаунту.
7. Выключите домашний компьютер и проверьте сообщение со своего телефона.
8. После простоя более 15 минут отправьте ещё одно сообщение и дождитесь
   пробуждения сервиса. Первый ответ может задержаться примерно на минуту
   или дольше, если Telegram повторяет запрос.

Не подключайте мониторинг, который постоянно открывает панель ради обхода
сна бесплатного тарифа. Бот обрабатывает входящие HTTP-запросы, а `/healthz`
проверяет готовность процесса без запросов к базе. В webhook-режиме до успешной
регистрации он отвечает 503; неверный токен или отклонённая конфигурация
завершают запуск. Ошибки `401`/`404`/`409` при работе webhook также снимают
готовность и завершают процесс. Временные ошибки регистрации повторяются
с учётом Telegram `retry_after`.
Это позволяет Neon
засыпать между обращениями.

## Доставка и ограничения

- Запускайте один экземпляр приложения. Webhook регистрируется с
  `max_connections=1`; пересекающиеся запросы получают 503 и ожидают повтора
  Telegram. Дополнительно аренда обработчика в PostgreSQL сериализует весь
  проход webhook и очереди ответов между процессами, в том числе при деплое.
  После сбоя аренда истекает за оставшийся бюджет обработки плюс 30 секунд;
  до этого Telegram получает 503. В простое фоновых запросов к БД нет.
- Успешный HTTP-ответ возвращается после обработки и отправки ответа либо
  терминального отказа доставки. Ошибки обработки и временные ошибки отправки
  возвращают 503. Сохранённые ответы повторяются без нового вызова LLM;
  `retry_at` и Telegram `retry_after` учитываются через очередь в PostgreSQL.
  Временные ошибки не отбрасывают ответ после трёх попыток: задержка растёт от
  5 секунд до 15 минут, с приоритетом большего `retry_after`. Фонового таймера нет;
  после прекращения повторов Telegram отправьте `/start`, когда наступит `retry_at`,
  чтобы запустить очередь без повторного создания расхода.
  Обычные ответы, ранее переведённые в `failed` после временных ошибок,
  можно вернуть в очередь командой `go run ./cmd/telegram-retry -update ID`
  с настроенным окружением приложения на компьютере оператора. Команда не
  повторяет мутации. Постоянные отказы, исключённые участники и устаревшие
  списки выбора не восстанавливаются; для списка нужен новый поиск.
- Повторы Telegram ограничены. Очень долгий простой или ошибка конфигурации
  могут привести к потере входящего сообщения. Это бесплатная схема для
  небольшого семейного использования, без гарантии непрерывной доступности.
- В бесплатных планах есть лимиты времени работы, базы, трафика, сборок и LLM.
  При их достижении сервис может остановиться. Смотрите условия в аккаунтах;
  не включайте платные планы, если вам требуется строго нулевая стоимость.
- Регулярно сохраняйте отдельные резервные копии Neon.
- Личный аккаунт главного пользователя и MFA обязательны локально и в облаке. Пароли хешируются
  PBKDF2-HMAC-SHA256 с отдельной солью и 600000 итераций, TOTP-секреты
  шифруются AES-GCM с привязкой к ID. В БД хранятся только хеши резервных кодов
  и токенов веб-сессий. Короткоживущая ссылка приглашения доставляется через
  Telegram и сохраняется в журнале доставки; после использования/15 минут
  она не даёт доступа.
- Публичные запросы авторизации ограничены 30 в минуту по источнику (IP,
  IPv6 — /64), в памяти экземпляра с ограниченным размером таблицы. На Render
  используется реальный IP из заголовка платформы; локально заголовки прокси
  не считаются доверенными. Медленная загрузка тела ограничена 3 секундами и
  не занимает слот проверки пароля.
- После 5 неверных кодов при правильном пароле вход блокируется на 15 минут.
  Счётчик находится в PostgreSQL и переживает перезапуск. Неверный пароль сам
  по себе не позволяет заблокировать владельца по известному ID: такие попытки
  ограничиваются по источнику. У действующей сессии отдельные бюджет проверки
  MFA и слот хеширования; операции ограничены 30 в минуту по сессии. Выход
  исключён из этих ограничений. Успешная смена пароля/MFA снимает блокировку
  входа и отзывает сессии. Ограничения веб-входа не блокируют Telegram-бота.
- Сессия действует 8 часов, cookie имеет HttpOnly, SameSite=Strict и Secure
  на HTTPS. Выход отзывает сессию в БД. Смена пароля или подтверждённая замена
  MFA отзывает все сессии аккаунта. Удаление ID из allowlist также закрывает
  доступ после перезапуска с обновлённой конфигурацией.
- Панель и REST API доступны только `PANEL_MASTER_USER_ID`. При каждом запросе
  проверяется владелец сессии; старые приглашения, пароли, резервные коды и
  сессии остальных пользователей больше не дают доступа. После изменения
  `PANEL_MASTER_USER_ID` перезапустите приложение. Для бота все ID остаются
  в `TELEGRAM_ALLOWED_USER_IDS`; расходы фильтруются по отправителю сообщения,
  включая главного пользователя. Бот не показывает чужие записи и итоги.
- TOTP не защищает
  от фишинга так же, как аппаратные ключи/passkeys: проверяйте адрес сайта.
- Облачные настройки требуют `sslmode=verify-full` для PostgreSQL и HTTPS для LLM API.

## Если что-то не работает

- **Build failed:** проверьте, что в репозитории есть `deploy/Dockerfile`,
  `go.mod`, `go.sum`, `render.yaml` и все исходники.
- **Ошибка DATABASE_URL:** скопируйте строку Neon заново, сохраняя TLS-параметры.
  Локальный адрес `db:5432` из Docker в облаке не работает.
- **Webhook registration failed:** проверьте токен и секрет в Environment,
  затем повторите деплой. Постоянные ошибки 4xx (кроме 408/429) останавливают
  процесс; временные повторяются с безопасным HTTP-кодом и задержкой в логе.
  Одновременно работающий локальный poller нужно остановить.
- **Бот молчит только у одного участника:** проверьте его числовой ID в
  `TELEGRAM_ALLOWED_USER_IDS`, личный чат и лог `Telegram access denied`.
- **Панель доступна, бот не понимает расходы:** проверьте ключ Groq, модель и
  доступные лимиты. `/start` обрабатывается без запроса к LLM.
- **401 в панели:** используйте Telegram ID главного аккаунта, его личный пароль и
  новый код аутентификатора. Общего логина `family` больше нет.
- **429 при входе:** после 5 неверных кодов при правильном пароле действует
  блокировка на 15 минут. Лимит источника/сессии восстанавливается через минуту.
  Проверьте время на телефоне: уже использованный TOTP-код не принимается.
  Действующая сессия позволяет выйти или сменить пароль/MFA независимо от
  публичного лимита входа.

## Восстановление и запуск без бота

При потере аутентификатора войдите с паролем и одним резервным кодом. На
странице «Безопасность» начните замену MFA, подтвердив пароль и ещё один
резервный код. Добавьте новый QR-код и подтвердите его. Старый аутентификатор
остаётся рабочим до подтверждения нового; после подтверждения старые резервные
коды и все сессии отзываются, показывается новый набор кодов.

Если потерян пароль или все вторые факторы, владелец БД может сбросить только
панельный аккаунт через SQL Editor Neon:

```sql
-- Замените 123456789 на PANEL_MASTER_USER_ID.
DELETE FROM panel_accounts WHERE user_id = 123456789;
```

Сессии этого аккаунта удалятся каскадно; расходы и Telegram-история сохранятся.
Затем главный пользователь снова отправляет `/panel` и настраивает аккаунт. Эта операция
доступна только владельцу БД, публичного обхода MFA или сброса через бота нет.

Без включённого Telegram оператор может создать ту же личную ссылку командой
`go run ./cmd/panel-invite -user 123456789`, предварительно задав окружение
приложения (`DATABASE_URL`, `PANEL_AUTH_KEY`, `PANEL_MASTER_USER_ID`,
`PUBLIC_BASE_URL`, allowlist). `-user` должен совпадать с `PANEL_MASTER_USER_ID`.
Передайте ссылку только главному пользователю по доверенному каналу.

## Возврат к локальному polling

Сначала остановите облачный сервис. Удалите Telegram webhook методом
`deleteWebhook` без `drop_pending_updates=true`, затем запустите локальное
приложение в режиме polling. Удалять webhook во время обычного облачного
перезапуска не нужно: Telegram должен сохранять и повторять сообщения.

Локальная и облачная базы независимы: перед переключением решите, где будут
храниться актуальные расходы, и при необходимости перенесите данные.
